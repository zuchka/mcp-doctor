# Scope Lab methodology template

## Study question

State whether a narrower Supabase MCP tool surface changes task completion for
the selected tasks. Describe the two MCP feature sets and two skill levels.

## Pinned configuration

Record Doctor, Evals, skill source, and MCP server revisions; model, reasoning,
harness, runtime, seed, task IDs, repetitions, timeout, and attempt cap. Include
manifest, contract, plan, and static report SHA-256 hashes.

## Execution and exclusions

State how four-cell blocks were shuffled and that attempts ran sequentially with
fresh ephemeral state. Give scheduled, scored, and infrastructure-error counts.
List every excluded task/repetition/condition and its error category.

## Outcomes

Give scored pass rates with denominators and Wilson intervals. Give the
all-scheduled sensitivity rates. Report the four prespecified paired contrasts
and descriptive difference in differences with complete-block counts. Include
named check counts and secondary tool-call, step, duration, token, docs, and
skill-loading summaries where observed.

## Interpretation

Discuss possible order effects, task selection, source-specific behavior, and
limitations of a small pilot. Do not present three tasks with one run each as
evidence of statistical significance or a universal scope advantage.

## Publication check

Share only the checked public export and reviewed Markdown. Keep raw result.json
files and credentials local. Verify that no prompt, tool arguments/results,
access tokens, sandbox URLs, or full transcripts are included.
